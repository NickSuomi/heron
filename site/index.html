Self-hosted review for GitLab merge requests

Every line passes the heron.

Heron reviews one merge request at its head, writes one report note, sets one label, and never approves, merges, or edits. It runs on your runner, with your model credentials.

Your runner

No hosted service. Heron runs in your CI job with your GitLab token. The only outside service it calls is the model vendor you configure.

Read-only eyes

Models see the reviewed commit through grep, list_files and read_file. They cannot run commands or change files. The token never reaches a model.

One note

One report note per merge request, updated in place on the next run, and one verdict label. No inline threads, no approvals, no merges.

Quick start

Alpha, version 0.0.0, not on npm. Needs Node 24 or later, pnpm 11 and git.

# install from source
git clone https://github.com/NickSuomi/heron.git
cd heron
pnpm install --frozen-lockfile

# validate the example config, offline
pnpm heron config check \
  --config heron.config.example.json

# review a real merge request, post nothing
pnpm heron review --mr 42 --dry-run

A real review needs a GitLab bot token with the api scope and one backend: your Claude Code CLI (claude-cli), your Codex CLI (codex-cli), or an OpenRouter API key (ai-sdk). In CI, add the manual heron-review job.
